# PDF-to-Word conversion and standalone PDF compression

## PDF to Word

Conversion Studio has three local DOCX output modes:

- **Editable Word document (default)**: reconstructs content as normal Word paragraphs, uses native Word tables for clearly ruled table structures (including some rows with merged cells), and inserts detected PDF image objects as separate Word image assets. It does not use a full-page image or positioned text boxes as the normal page content. The PDF page dimensions are retained; Word is allowed to wrap and reflow edited text naturally. Logos/photos that overlap table regions are inserted into the detected table cells when geometry supports this.
- **Layout-preserving**: uses the earlier fixed-page reconstruction path, retaining a high-resolution page-artwork layer with supported text rebuilt as positioned editable Word frames. Choose this for visual alignment over normal text-flow editing.
- **Visual replica**: preserves each page as a high-resolution page image, prioritizing appearance rather than semantic editability.
- **Hybrid OCR**: when enabled, the renderer sends a locally rendered PNG to the Electron main process. The main process launches Tesseract without a shell, parses word-level TSV coordinates/confidence, and merges OCR words with the native PDF text layer using both geometry and text evidence. OCR is local; PDF pages are not uploaded. Tesseract and the selected `*.traineddata` files are optional and are not bundled in this source archive by default. See `resources/ocr/README.md`.
- **Quality checks**: the generated DOCX is reopened as a ZIP, required package parts and relationships are checked, document and required-part XML is checked for well-formedness in the renderer, and the serialized DOCX ZIP is reopened with CRC checking. Coverage reports include missing/extra tokens for editable and source text and adjacent-token reading-order continuity. The page text-mask similarity metric compares canvas pixels in masked text areas; it is an estimate, not a render-and-compare of the final Word document.
- **Table detection**: clear ruled grids are rebuilt as native Word tables. The editable-mode detector permits partial interior vertical rules so a row may span columns where the PDF has merged cells. Pages without tables remain ordinary flowing paragraphs/images rather than being forced into a table. Borderless or ambiguous tables cannot be reliably inferred from geometry and may become ordinary paragraphs.
- **Image/text separation**: separate image assets are cropped from a text-free PDF.js render when possible; ordinary photo regions with real overlaid captions retain the full render, while wide header composites use the text-free crop to prevent duplicated headings while retaining the banner artwork as a separate asset. Crop decisions use the full native/OCR geometry even when photo-contained text is excluded from the editable text stream. Side-by-side external photos use explicit spacer columns in the borderless Word image table, instead of relying on whitespace at a cell boundary. Image sizing preserves the source PDF's physical placement dimensions unless available page/cell width requires a proportional fit; arbitrary global image-height caps are avoided. Form XObject transforms are applied when estimating nested image positions.
- **Scanned pages**: when OCR returns usable text for a scan-only page, the converter preserves the page artwork and adds editable OCR text frames at the recognized locations. If OCR is unavailable or produces no usable text, the original page remains an image instead of producing a blank page. OCR text and positioning should be reviewed.
- **Typography**: flowing paragraphs use extracted font mapping and measured baseline pitch where available. This improves line spacing but cannot reproduce every font, kerning pair, or Word/Acrobat line-break decision exactly.

### Accuracy boundary

This semantic conversion is designed to behave more like a regular Word document, but it is not Adobe Acrobat Pro's proprietary conversion engine and does not guarantee exact reconstruction for every arbitrary PDF. In particular:

- The converter extracts placed image objects by cropping their rendered PDF regions. This preserves visible photos/logos as separate Word image assets, but does not guarantee original byte-for-byte image data and can include nearby pixels for transparent/overlapping PDF objects. Wide composite image regions overlapping native text are retained as separate assets only when the text-free crop can prevent a duplicate heading; that heading remains editable. Complex vector drawings, transparency, and unrecognized page decorations may not be reconstructed as independent Word objects.
- Some text with unsupported orientation, RTL/vertical scripts, or variable/photographic backgrounds may not be fully editable. Scan-only pages are kept as a page image when there is no reliable native text layer rather than generating fabricated text.
- OCR layout/style is estimated from word boxes and confidence; OCR can misrecognize text and does not recreate true source font metadata.
- Table boundary and merged-cell detection are geometric heuristics. Borderless tables, shading, all cell-specific styles, bullets/multilevel numbering, and actual semantic headers/footers are not guaranteed. A document with columns, floating callouts, or precise wrap-around art may need manual cleanup in Word.
- Normal Word flow intentionally prioritizes editable paragraphs and tables over pixel-identical placement. Use Layout-preserving or Visual replica when exact positioning/appearance is more important than natural editing.
- Font family mapping chooses an available/metric-compatible family and cannot embed or reproduce every proprietary, subsetted, or missing PDF font exactly.
- The output's comparison number is a masked-text canvas similarity estimate. Final DOCX rendering is not automatically rasterized by Word/LibreOffice and compared pixel by pixel by the app.

Review the exported file in Microsoft Word and compare against the source before using it as a legally, medically, or commercially critical document. For Acrobat-class semantic fidelity, integrate a purpose-built PDF-to-Office SDK and a validated OCR engine/model distribution.

## Standalone Compress PDF

Open **Compress PDF** from Conversion Studio or quick-launch. The workflow analyzes the selected source, prepares a preview, compares size and structure checks, then saves a separate `-compressed.pdf` copy only when the user chooses Save.

- **PDF analysis:** PDF.js counts pages, text items/characters, image paint operations, annotations, links, form widgets, bookmarks, attachments, and page geometry. A best-effort `pdf-lib` object scan estimates image stream bytes, largest image payload, embedded font streams, total stream payload and duplicate-image candidates. Raw object statistics may be unavailable for encrypted or unusual PDFs; those fields are marked unavailable instead of guessed.
- **Lossless only:** tries the local PDF toolkit optimizer and preserves the original when it cannot produce a smaller file. It does not rasterize pages.
- **Smart object compression:** when Ghostscript is available, its `pdfwrite` high-level device selectively down-samples images by effective display resolution, recompresses color/gray image streams, reuses duplicate images, compresses streams, and compresses/subsets fonts. If Ghostscript is unavailable (as in a source build that does not stage its licensed runtime), a built-in MIT-licensed image-object optimizer recompresses supported embedded raster images in place. It keeps native text, vectors, links, and forms instead of flattening whole pages. Unsupported codecs may be skipped. The actual result is measured and retained only when it is smaller and passes structural checks.
- **Presets and target size:** High quality, Recommended, Smaller file, and Smallest file select DPI/quality profiles. Target size accepts MB or a percentage and tries progressively stronger profiles, choosing the smallest safe candidate found and reporting when the target is missed.
- **Visual preview and integrity checks:** renders a selected page of the original and candidate side by side. Before accepting a smart rewrite, the app checks page count/geometry, selectable text token coverage, links, form widgets, embedded attachment counts, bookmarks and annotation counts. When the smart result fails hard checks, it is rejected and the smaller safe result (lossless/original) is retained.
- **Explicit raster fallback:** whole-page rasterization is disabled by default. Users must opt in before applying it. Rasterization can lose searchable text, links, forms, vectors, bookmarks, attachments, accessibility structure, and signatures; it is only offered as a last resort. True black-and-white page output requires this fallback; object-preserving grayscale is supported by Ghostscript.
- **Signed PDFs:** if a signature marker is found, the app skips compression to avoid silently invalidating the signed document. Signature detection is conservative and cannot replace specialist signature validation.
- **Password and report:** a source password can open protected PDFs; an optional AES-256 output password is applied when saving. The report calculates final size again after protection because encryption can add bytes.

### Smart compression engine availability

The app detects Ghostscript from `PATH` or `resources/ghostscript/bin/gswin64c.exe` in a Windows package (or `gs` on Unix-like development systems). To make the smart optimizer available in a release, stage a complete, licensed Ghostscript runtime in `resources/ghostscript` before packaging. PDF Studio does not download it automatically. Ghostscript's `pdfwrite` reconstructs a new PDF, not a byte-preserving edit; non-marking metadata, comments, links, bookmarks, forms, and specialized structures may not all survive. The app rejects candidates when its hard structural checks detect missing text, links, form widgets, or attachments, but this is not a full ISO conformance or signature-validation system.

**If Ghostscript is unavailable:** the built-in embedded-image optimizer is tried after the lossless pass, including a bounded target-size profile search. It recompresses compatible image XObjects without intentionally rasterizing native text/vector content. If no supported image objects can be safely made smaller (for example, because the PDF uses unsupported image codecs or is encrypted), the original/lossless candidate is retained and the report explains the limitation. Whole-page raster fallback remains explicitly opt-in.

## Build and checks

Run `npm ci`, then `npm run web:build` or `npm run build:win`. Tests: `npm run test:pdf` exercises validation, option normalization, measured lossless/target flows and summary metrics; `npm run test:access` runs the existing access-policy, telemetry, and review-queue checks. A fresh Vite/Windows package build must be performed in an environment with npm registry access.
